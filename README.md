# AI-OS

Enterprise AI Asset Operating System - 企业 AI 资产操作系统

## 定位

统一管理企业一切 AI 资产（规则、技能、提示词、知识库、MCP 工具），让 AI 编辑器退化成纯输入输出终端。

## 核心架构设计

### 整体架构

```
Trae 编辑器（空壳）
      │
      ▼
服务端（AI 大脑）── 决策、管控、存储
      │
      ▼
客户端（AI 手脚）── 执行、本地操作、硬件访问
```

### 双层 AI 架构

```
┌─────────────────────────────────────────────┐
│            服务端（AI 大脑）                    │
├─────────────────────────────────────────────┤
│  干活AI（强模型）      │
│  - GPT-4o / Claude 3.5 / DeepSeek V3       │
│  - 负责代码生成、复杂推理、创意输出           │
└─────────────────────────────────────────────┘
                      ↓ 监督层
┌─────────────────────────────────────────────┐
│  监督AI（便宜模型）                           │
│  - GPT-3.5 / Claude Haiku / Qwen-Turbo      │
│  - 实时监控所有 AI 调用，记录违规行为          │
│  - 当违规累积到阈值，触发蒸馏引擎              │
└─────────────────────────────────────────────┘
                      ↓ 触发
┌─────────────────────────────────────────────┐
│  评审AI（中等模型）                           │
│  - GPT-4o-mini / Claude 3 Sonnet             │
│  - 分析违规记录，生成新规则                   │
│  - 自动注入到规则引擎                         │
└─────────────────────────────────────────────┘
```

### 六大核心引擎

#### 1. 代理网关（Gateway）

- **职责**：统一 API 入口，流量调度，负载均衡
- **功能**：
  - 多模型路由（根据任务复杂度自动选择模型）
  - 请求缓存（相同请求命中缓存，直接返回）
  - 限流熔断（保护模型接口，防止超限）
  - 审计日志（记录所有 AI 调用，供监督 AI 分析）

#### 2. 规则引擎（Rule Engine）

- **职责**：管理所有 AI 行为约束，多维度生效
- **功能**：
  - 多维度规则管理（语言、角色、项目、部门）
  - 规则版本控制（灰度发布、快速回滚）
  - 违规检测与拦截（注入到 prompt 中，实时拦截）
  - 规则热更新（无需重启服务）
- **规则分层**：
  ```
  宪法层（不可违背）→ 公司规范层 → 部门规范层 → 项目规范层
  ```

#### 3. 技能引擎（Skill Engine）

- **职责**：管理可复用的 AI 技能，支持版本控制
- **功能**：
  - 技能注册与发现（类似插件系统）
  - 技能版本管理（支持多版本并存）
  - 技能依赖管理（自动解决依赖关系）
  - 技能编排（多个技能组合成工作流）
- **示例技能**：代码审查、API 调试、数据库查询、文档生成

#### 4. MCP 引擎（MCP Engine）

- **职责**：管理所有 MCP 工具，实现工具审计与编排
- **功能**：
  - MCP 工具注册中心（统一管理所有工具）
  - 工具权限控制（谁可以调用哪些工具）
  - 工具调用审计（记录所有工具调用，分析使用频率）
  - 工具链编排（多个工具串联执行）
- **解决截断问题**：升级后由中台控制整个链路，不再受编辑器限制

#### 5. 提示词引擎（Prompt Engine）

- **职责**：管理所有提示词模板，支持变量注入和版本控制
- **功能**：
  - 提示词模板管理（类似代码模板）
  - 提示词变量注入（运行时动态填充）
  - 提示词版本控制（A/B 测试不同版本效果）
  - 提示词优化建议（基于效果数据自动优化）
- **示例模板**：
  ```
  你是 {role}，当前项目是 {project_name}，部门是 {department}。
  请遵循以下规则完成 {task}：
  {rules}
  ```

#### 6. 知识库引擎（Knowledge Engine）

- **职责**：管理企业知识库，提供语义检索能力
- **功能**：
  - 向量化存储（将文档转换为向量）
  - 语义检索（基于向量相似度搜索）
  - 知识图谱（构建实体关系网络）
  - 知识更新（自动同步最新文档）
- **应用场景**：公司规范、技术文档、业务知识、历史经验

### 蒸馏引擎（Distillation Engine）

**工作流程**：

```
违规行为监控
     │
     ▼
监督AI实时检测 → 记录违规（格式：{行为, 上下文, 严重程度}）
     │
     ▼
违规累积判断（达到阈值？）
     │ Yes
     ▼
评审AI分析 → 生成新规则（解释为什么违规，应该如何做）
     │
     ▼
自动注入规则引擎 → 灰度测试 → 全量发布
```

**关键价值**：
- 持续优化 AI 行为，从人工被动管理 → 机器主动学习
- 规则越来越多，AI 越来越聪明
- 最终形成"AI 管治 AI"的自治体系

## 客户端/服务端职责划分

### 划分原则

| 维度 | 服务端（大脑） | 客户端（手脚） |
|------|--------------|--------------|
| **核心职责** | 决策、管控、存储 | 执行、本地操作、硬件访问 |
| **数据存储** | 集中存储所有资产 | 仅存储本地缓存 |
| **密码等敏感信息** | 不存储密码 | 持有密码，不离开本地 |
| **AI 推理** | 所有 AI 调用 | 无 AI 推理能力 |
| **网络访问** | 访问外网（模型 API） | 访问内网资源 |
| **文件系统** | 仅管理代码库 | 访问全量本地文件 |
| **硬件访问** | 无 | CPU/GPU、USB、显示器 |

### 典型场景示例

#### 场景 1：数据库查询

**安全架构**：
```
用户输入 SQL
    │
    ▼
服务端（校验权限 + SQL 合法性）
    │ 通过
    ▼
返回 SQL + 加密命令到客户端
    │
    ▼
客户端（持有密码）执行 SQL
    │
    ▼
返回结果到服务端（可选：持久化到知识库）
```

**关键点**：
- 服务端校验：防止 SQL 注入、越权访问
- 客户端执行：密码不离开本地，符合安全合规
- 结果回传：可选回传到服务端，用于后续 AI 分析

#### 场景 2：代码审查

**执行流程**：
```
用户提交代码变更
    │
    ▼
服务端（提取代码 diff）
    │
    ▼
调用规则引擎（注入项目规范 + 部门规范）
    │
    ▼
调用干活AI（GPT-4o 执行审查）
    │
    ▼
监督AI（检查回复是否包含敏感信息）
    │
    ▼
返回审查报告到客户端
```

#### 场景 3：MCP 工具调用

**传统方式（有截断问题）**：
```
Trae 编辑器 → MCP 工具 → 返回结果（可能超长被截断）
```

**AI-OS 方式（无截断）**：
```
Trae 编辑器 → 服务端（代理网关） → MCP 引擎 → 客户端执行
    │                                                    │
    └────────────────────────────────────────────────────┘
                        流式返回结果（可分段接收）
```

## 从 Pointend 借鉴的设计思想

### 借鉴部分

1. **双层 AI 架构**：强模型干活，便宜模型监督，降低成本
2. **规则宪法体系**：多层级规则，自动降级，避免硬编码
3. **Rust 加速**：高频场景用 Rust 实现（如规则匹配、向量化检索）
4. **自动蒸馏机制**：从人工管理规则 → AI 自动生成规则

### 超越部分

1. **范围聚焦**：Pointend 想做"代码操作系统"，AI-OS 聚焦"AI 资产操作系统"
2. **轻量落地**：不追求"重写编辑器"，而是"剥离 AI 能力"，改造成本低
3. **客户端/服务端分离**：明确职责边界，解决安全、隐私、性能问题
4. **企业场景优化**：权限控制、审计日志、知识库、技能编排等企业特性

## 技术栈

### 服务端

| 组件 | 技术 |
|------|------|
| 后端框架 | Python (FastAPI) |
| 向量检索 | Qdrant / Milvus |
| 数据库 | PostgreSQL |
| 缓存 | Redis |
| 消息队列 | RabbitMQ / Kafka |
| 高性能加速 | Rust (PyO3 绑定) |

### 客户端

| 组件 | 技术 |
|------|------|
| 桌面框架 | Electron + Python |
| UI 框架 | Vue 3 + Element Plus |
| 本地执行 | Python (本地脚本) |
| 跨进程通信 | WebSocket / IPC |

## 核心特性

1. **统一管控**：所有 AI 资产集中管理，避免分散
2. **安全合规**：密码不离开本地，权限精细化控制
3. **持续进化**：蒸馏引擎让 AI 越来越聪明
4. **成本优化**：双层 AI 架构，降低总体调用成本
5. **可观测性**：全链路审计日志，问题可追溯
6. **灵活扩展**：插件化技能系统，轻松接入新能力
