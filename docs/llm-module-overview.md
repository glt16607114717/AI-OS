# AI-OS 大模型模块功能清单

> 版本：0.1.2 | 更新日期：2026-06-07
> 本文档梳理 AI-OS 对 Trae 编辑器大模型请求的全部改造点，供风险评估。

---

## 架构概览

```
Trae 编辑器
    ↓ HTTP 请求（OpenAI 兼容格式）
AI-OS 代理层（localhost:18731）
    ↓ 拦截、改造、转发
大模型 API（智谱等）
    ↓
AI-OS 代理层
    ↓ 响应透传
Trae 编辑器
```

**核心原则**：AI-OS 作为本地透明代理，拦截编辑器发出的 `/v1/chat/completions` 请求，在转发前对请求体进行改造，对响应透传回编辑器。

---

## 一、请求改造（Prompt 工程）

### 1.1 上帝指令注入

| 项 | 说明 |
|----|------|
| 功能 | 将用户自定义的"上帝指令"注入到 system prompt 最前面 |
| 位置 | system 消息的最顶部，标签 `[HIGHEST PRIORITY - 上帝指令]` |
| 开关 | 上帝指令页面"已启用"开关 |
| 存储 | `C:\ProgramData\AI-OS\config\god_rules.json` |
| 风险等级 | 低 — 仅在 system prompt 前追加文本 |

### 1.2 用户规则提取

| 项 | 说明 |
|----|------|
| 功能 | 从 user 消息的 `<trae_rules_context>` 标签中提取用户规则，剪切到 system prompt |
| 原因 | 编辑器将用户规则放在 user 消息中（可能被上下文截断），提升到 system 可确保优先级 |
| 标签 | `[用户规则 - 高优先级]` |
| 开关 | "提示词优化"开关（与上帝指令独立） |
| 风险等级 | 中 — 改变了规则在请求体中的位置 |

### 1.3 system-reminder 去重

| 项 | 说明 |
|----|------|
| 功能 | 去除 user 消息中重复出现的 `<system-reminder>` 块 |
| 目标 | Response Language Settings、Terminal Status、Skill 提醒（每条 user 消息都重复注入） |
| 策略 | 第一次出现保留，后续重复移除 |
| 开关 | "提示词优化"开关 |
| 风险等级 | 中 — 移除了编辑器认为必要的重复提醒 |

### 1.4 工具描述压缩

| 项 | 说明 |
|----|------|
| 功能 | 压缩编辑器传入的 5 个官方工具描述（RunCommand / Task / TodoWrite / SearchCodebase / Skill） |
| 压缩率 | 67% ~ 92%（约节省 14,000 chars / 请求） |
| 原则 | 保留功能定义和使用约束，去除示例、教程、重复说明 |
| 开关 | "提示词优化"开关 |
| 风险等级 | 中 — AI 收到的工具描述被精简，可能影响行为 |

### 1.5 工具移除

| 项 | 说明 |
|----|------|
| 功能 | 从请求的 tools 数组中移除指定工具 |
| 当前移除 | `DeleteFile`（该工具会触发编辑器二次确认弹窗） |
| 替代方案 | 由自定义技能 `safe-exec` 替代 |
| 风险等级 | 高 — AI 无法使用被移除的原生工具 |

## 二、路由与转发

### 2.1 策略路由

| 项 | 说明 |
|----|------|
| 功能 | 根据用户配置的策略（固定/轮询）选择厂商和模型 |
| 策略类型 | 固定策略（指定厂商+模型）、轮询策略（多厂商加权轮询） |
| 配置 | 策略编辑器页面，支持多个策略、激活其中一个 |
| 故障转移 | 轮询策略自动跳过不可用 key |

### 2.2 故障转移

| 项 | 说明 |
|----|------|
| 功能 | 当主厂商请求失败时，自动尝试其他可用厂商 |
| 触发条件 | HTTP 非 200、超时、连接失败 |
| 策略 | 从 `llm_config.get_all_routes_for_failover()` 获取备选列表，排除已失败厂商 |
| 日志 | 每次故障转移记录到操作日志 |

### 2.3 用量降级

| 项 | 说明 |
|----|------|
| 功能 | 智谱 API key 用量超阈值时自动降级模型 |
| 三层分级 | < 70% 正常（glm-5.1）/ 70%-90% 降级（glm-4.7）/ > 90% 耗尽（跳过该 key） |
| 粒度 | 每个 key 独立判断，非全局降级 |
| 轮询策略 | 耗尽 key 自动跳过 |
| 固定策略 | 耗尽 key 返回 429 错误 |
| 监控频率 | 每 10 分钟查询一次智谱用量 API |
| 开关 | 用量监控页面开关 |

## 三、数据记录

### 3.1 请求/响应转储

| 项 | 说明 |
|----|------|
| 功能 | 每次 LLM 请求保存完整的请求体和响应体到独立 JSON 文件 |
| 路径 | `C:\ProgramData\AI-OS\logs\requests\{timestamp}.json` |
| 保留 | 最近 20 个文件，自动清理 |
| 内容 | 请求体（注入后）+ 响应体 + 厂商信息 + 耗时 + 错误信息 |

### 3.2 操作日志

| 项 | 说明 |
|----|------|
| 功能 | 记录所有大模型相关操作的人可读日志 |
| 存储 | SQLite（`C:\ProgramData\AI-OS\logs\agent.db` 的 llm_log 表） |
| 保留 | 最多 1000 条，自动裁剪 |
| 分类 | request / route / downgrade / quota / failover / config / error |
| 展示 | 操作日志页面，1 秒自动刷新，支持分类筛选和清空 |

### 3.3 用量统计

| 项 | 说明 |
|----|------|
| 功能 | 记录每次请求的 token 用量、延迟、模型、厂商等，生成统计报表 |
| 存储 | SQLite（llm_stats 表） |
| 展示 | 数据看板页面，按厂商/模型/天维度展示 |
| 保留 | 默认 30 天，支持手动清理 |

## 七、风险评估

| 风险项 | 等级 | 说明 | 缓解措施 |
|--------|------|------|----------|
| 请求体改造导致 AI 行为异常 | 中 | 上帝指令/规则提取/去重改变了 AI 看到的内容 | 可通过开关逐项关闭 |
| 工具压缩导致 AI 误用工具 | 中 | 精简描述可能丢失约束信息 | 保留核心约束，可关闭 |
| 工具移除导致功能缺失 | 高 | DeleteFile 被移除，AI 无法使用原生删除 | 由 safe-exec 技能替代 |
| 故障转移导致意外行为 | 低 | 请求可能被转发到非预期厂商 | 日志记录每次转移 |
| 用量降级导致模型降级 | 低 | 自动从 glm-5.1 降到 glm-4.7 | 日志记录，可关闭监控 |
| 代理层崩溃导致编辑器不可用 | 中 | Agent 挂掉 = 所有 LLM 请求失败 | Watchdog 自动重启 |
