## 三、异常报告（★重点模块）

异常报告模块是交付运维中最复杂的子模块，实现了完整的异常闭环管理流程：**异常报告 → 检讨单 → 评审单 → 核准单 → 申诉单**，涵盖成本核算、责任人判定和奖惩措施。

### 3.1 完整闭环流程

```
异常报告发起 → 生成检讨单 → 填写检讨（过程描述+原因分析+改善措施+责任人）
    → 检讨审批通过 → 确定评审人 → 评审（过程描述+主要原因+奖惩方案）
    → 评审完成 → 成本核算（可选）→ 核准（主要原因+责任人+惩罚措施+成本核算）
    → 被罚人员确认/申诉
        ├── 确认接受 → 流程结束
        └── 提交申诉 → 新一轮评审 → 核准 → 再次确认/申诉（最多3次）
            └── 驳回申诉 → 维持原判 → 流程结束
```

**一级状态（first_status）：** 1=检讨 → 2=评审 → 3=第一次申诉 → 4=第二次申诉 → 5=第三次申诉 → 6=彻底完结

**二级状态（second_status）：** 1=未开始 → 2=已开始（检讨全部审批通过）→ 3=确定评审人 → 4=评审已完成 → 5=损失核算（可跳过）→ 6=损失核算完成 → 7=核准完成

### 7.2 工单状态流转

```
创建工单 → 保存配置（名称/时间/负责人/交付经理等）
    → 设置确认人（客户负责人/项目负责人/项目助理/交付工程师/交付总监等）
    → 各确认人逐一确认 → 工单启动（is_start=2）
    → 任务执行中（status=2进行中）
    → 任务全部完成 → 工单完成（status=3已完成）
    
异常路径：
    → 超期未完成 → 已延期（status=4，abnormal_status=2）
    → 即将超期 → 预警（status=5，abnormal_status=3）
```

## 附录：模块间关系总览

```
交付阶段配置（Node）──┐
交付任务配置（Task）──┤
                      ├──→ 交付模板（Template）──→ 交付工单（WorkOrder）
交付客户字段（Field）─┘         │                        │
                                │                        ├──→ 工单任务（Task）
                                │                        ├──→ 确认人（ConfirmUser）
                                │                        ├──→ PMC日志
                                │                        └──→ 停机日志
                                │
模拟卡位（AnalogStation）←── 关联工单 ←── 交付工单
        │
        └──→ 摄像头（Camera）←→ 绑定/替换/解绑
                                    └──→ WebRTC实时播放

交付计划管理（Plan）──→ 月计划/年计划/目标/日志
        │
        └──→ 异常报告（AbnormalReport）
                ├──→ 检讨单（Rectification）
                ├──→ 评审单（Review）→ 评审人分配
                ├──→ 核准单（Check）
                │       ├──→ 责任人判定
                │       ├──→ 奖惩措施
                │       └──→ 成本核算
                └──→ 申诉单（Appeal）→ 最多3次申诉
```
