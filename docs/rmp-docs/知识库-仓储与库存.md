# RMP 仓储与库存模块知识库

## 一、仓库管理

### 1.1 模块概述

仓库管理模块负责维护仓库和仓位的层级结构，支持多公司、多仓库体系。仓库分为"系统仓"和"非系统仓"（storehouse_type=2），每个仓库下可挂载多个仓位（is_space=1），形成"仓库→仓位"两级层级树。支持启用/禁用、仓管人员绑定、库存可用性控制。

## 二、仓库盘点

### 2.1 模块概述

仓库盘点模块实现完整的盘点流程：创建盘点任务 → 执行盘点 → 审核 → 盈亏处理。支持全盘和抽盘两种模式，支持单人盘点，可选择是否锁库（盘点期间锁定库存操作）。

**盘点状态流转**：待盘点(1) → 盘点中(3) → 盘点完成(4) → 待盈亏处理(2) → 已处理

### 2.2 核心表

| is_lock | tinyint | 是否锁库：1是，2否 |
| material_group_id | int | 产品类别ID（抽盘用） |

### 2.3 盘点流程

1. **创建盘点任务**：选择仓库、盘点范围（全盘/抽盘）、盘点人、是否锁库。抽盘模式需指定产品类别和物料。
2. **执行盘点**：调用 `execInventory` 接口，系统根据盘点范围生成盘点明细。全盘模式拉取仓库所有库存产品；抽盘模式按物料类别筛选。
3. **扫码盘点**：支持通过 `product_no` 扫码获取出入库信息（`getStockInfo`），也支持 Excel 批量上传盘点结果（`uploadResult`）。
4. **审核**：审核前会检查是否有未盘点的产品（`getInventoryNum`），审核通过后进入盈亏处理环节。
5. **盈亏处理**：调用 `dealInventoryOrder` 生成盘盈/盘亏单（r_inventory_order），盘盈生成入库单，盘亏生成出库单。

## 三、盘盈盘亏

### 3.1 模块概述

盘盈盘亏是盘点流程的后续环节。盘点审核后，系统根据盘点明细中的盈亏数（profit_num = 盘点数 - 库存数）自动生成盘盈盘亏单。盘盈（type=1）生成入库单增加库存，盘亏（type=2）生成出库单减少库存。

### 3.2 核心表

#### r_inventory_order（盘盈盘亏单）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int PK | 主键 |
| order_no | varchar(50) | 盘盈亏单编号 |
| inventory_id | int | 盘点单ID |
| stock_id | int | 盘点仓库ID |
| space_id | varchar(120) | 盘点仓位ID（逗号分隔） |
| profit_number | int | 盘盈数 |
| type | tinyint | 类型：1盘盈，2盘亏 |
| status | tinyint | 状态：1未审核，2已审核，3反审核 |

**索引**：PRIMARY(id), idx_order_no, idx_stock_id

#### r_inventory_order_detail（盘盈盘亏明细）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int PK | 主键 |
| order_id | int | 盘盈亏单ID |
| stock_id | int | 挂账仓库ID |
| space_id | int | 挂账仓位ID |
| stock_in_id | int | 盘点仓库ID |
| space_in_id | int | 盘点仓位ID |
| material_id | int | 物料ID |
| product_no | varchar(50) | 机器人编号 |
| number | int | 库存数量 |
| inventory_num | int | 盈亏数 |

**索引**：PRIMARY(id), idx_order_id, idx_material_id, idx_product_no

### 3.3 业务逻辑

- 盘点审核后触发盈亏处理，遍历盘点明细中 profit_num ≠ 0 的记录
- profit_num > 0 → 盘盈 → 生成盘盈单（type=1），后续生成调拨入库单增加库存
- profit_num < 0 → 盘亏 → 生成盘亏单（type=2），后续生成调拨出库单减少库存
- 盘盈盘亏单审核通过后，实际更新库存数据

|------|------|------|
| /api/admin/inventory-order/list | GET | 盘盈盘亏列表（需传type：1盘盈/2盘亏） |
| /api/admin/inventory-order/detail-list | GET | 盘盈盘亏明细列表 |
| /api/admin/inventory-order/info | GET | 详情 |
| /api/admin/inventory-order/audit | POST | 审核 |
| /api/admin/inventory-order/export | GET | 导出 |

- `storehouseManage/inventoryLoss/` — 盘亏列表
- `storehouseManage/inventoryLossDetails/` — 盘亏详情

## 四、库存统计

### 4.1 模块概述

库存统计模块提供多维度的库存查询能力，包括按仓库仓位统计可用库存、库存明细、产品明细、类目树筛选、仓位校验和库存日志。通过视图 `r_view_material_stock_count` 和 `r_view_material_stock` 实现聚合查询。

### 4.2 核心表/视图

#### r_view_material_stock（物料库存视图）

| 字段 | 类型 | 说明 |
|------|------|------|
| material_id | int | 物料ID |
| stock_id | int | 仓库ID |
| space_id | int | 仓位ID |
| type | tinyint | 类型：1在库，2在途 |
| stock | decimal(33,0) | 库存数量 |

该视图按 material_id + stock_id + space_id + type 维度聚合库存数据，区分"在库"和"在途"两种状态。

#### r_view_material_stock_count（物料库存统计视图）

| 字段 | 类型 | 说明 |
|------|------|------|
| stock_id | int | 仓库ID |
| space_id | int | 仓位ID |
| material_id | int | 物料ID |
| level_one | int | 一级类目ID |
| level_two | int | 二级类目ID |
| stock | decimal(33,0) | 在库数量 |
| transit | decimal(33,0) | 在途数量 |
| avail | decimal(33,0) | 可用数量 |

**库存计算逻辑**：
- `stock`（在库）= 已入库且未出库的产品数量
- `transit`（在途）= 已出库但未入库确认的产品数量
- `avail`（可用）= stock - 已锁定/已分配数量
- 库存统计按 material_id + stock_id + space_id 三维度汇总

#### r_view_log_produce_storehouse（产品仓库日志视图）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int | 日志ID |
| material_stock_detail_id | int | 库存明细ID |
| origin_storehouse_id | int | 来源仓库ID |
| origin_space_id | int | 来源仓位ID |
| storehouse_id | int | 目标仓库ID |
| space_id | int | 目标仓位ID |
| type | tinyint | 类型：1调拨，2其他，3盘点，4部署 |
| log_user_id | int | 操作用户ID |
| start_time/end_time | int | 开始/结束时间 |
| product_no | varchar(30) | 产品编号 |
| material_id | int | 物料ID |
| company_id/customer_id/customer_ground_id/work_station_id | int | 关联业务维度 |

该视图记录产品在仓库间的流转日志，支持按调拨、其他、盘点、部署四种类型追溯。

### 4.3 库存统计功能

1. **按仓库仓位统计可用库存**（`stock-list`）：按物料维度展示各仓库仓位的在库/在途/可用数量，支持按类目、物料编号/名称、仓库编号/名称筛选。
2. **库存明细**（`detail-list`）：展示每个物料在各仓库仓位的详细库存信息。
3. **产品明细**（`product-detail` / `product-list`）：按物料+仓库+仓位查看具体产品（识别码级别），支持按机器人编号、状态、协议日期筛选。
4. **类目树**（`group-tree`）：一二级物料类目树，用于库存统计的类目筛选。
5. **仓位校验**（`check-space-stock`）：校验指定仓库仓位下某物料的库存是否足够。
6. **库存日志**（`stock-log-v1`）：按物料查询库存变动日志，支持按订单类型、订单号、序列号、仓库、时间范围筛选。

## 五、调拨单

### 5.1 模块概述

调拨单是仓储调拨流程的起点，用于发起物料从调出仓库到调入仓库的转移申请。调拨单可关联上岗单（post_statement_id）或交付工单（delivery_order_id），支持设备调拨场景。调拨单审核通过后，可生成调拨出库单。

| work_station_ids | varchar(255) | 工位ID（逗号分隔） |
| delivery_order_id | int | 交付工单ID |

**索引**：PRIMARY(id), idx_transfer_no

#### r_transfer_order_material（调拨单物料明细）

**索引**：PRIMARY(id), idx_order_id, idx_material_id

### 5.3 调拨流程链路

```
调拨申请（r_transfer_order）
    ↓ 审核通过
调拨出库（r_transfer_outbound_order）
    ↓ 审核通过，库存减少
调拨入库（r_transfer_warehouse_order）
    ↓ 审核通过，库存增加
```

- 调拨单保存时，系统校验调拨数量 > 0，调入仓库必填
- 调拨单可关联上岗单，自动计算需求数量（demand_num）
- 设备调拨（saveDeviceTransfer）支持按上岗单或工位维度发起

## 六、调拨出库单

### 6.1 模块概述

调拨出库单处理物料从仓库发出的业务，支持三种出库类型：
- **调拨出库**（source=1）：由调拨单触发的标准出库流程
- **其他出库**（source=2）：非调拨场景的出库（如报废、领用等）
- **销售出库**（source=3）：关联销售订单的出库

出库单审核通过后，对应仓库仓位的库存减少，并生成调拨入库单（调拨出库场景）或直接完成出库（其他出库/销售出库）。

2. **其他出库**：独立创建，需填写出库单号、出库日期、出库仓库、出库产品明细、供应商信息。
3. **销售出库**：关联销售订单（sale_order_id），需填写业务员、物流信息等。

**扫码出库**：支持通过序列号（serial_no）或识别码（product_no）扫描获取产品信息，校验产品是否在指定仓库仓位中。

## 七、调拨入库单

### 7.1 模块概述

调拨入库单处理物料入库业务，支持五种入库来源（source字段）：
- **调拨入库**（source=1）：由调拨出库单触发的标准入库
- **其他入库**（source=2）：非调拨场景的入库（如盘盈入库、赠送等）
- **样品入库**（source=4）：样品类物料入库
- **夹治具入库**（source=5）：夹具/治具类物料入库
- source=3 为销售退货入库

入库单审核通过后，对应仓库仓位的库存增加。入库单明细包含价格信息（未税单价、设备使用费），用于财务核算。

### 7.3 入库流程

1. **调拨入库**：由调拨出库单触发，收货人确认入库，选择入库仓库和仓位。
2. **其他入库**：独立创建，需填写入库单号、入库日期、入库仓库、产品明细、供应商信息。
3. **样品入库**：独立编号（sample-last-no），用于样品类物料入库。
4. **夹治具入库**：独立编号（fixture-last-no），用于夹具治具类物料入库。

**设备使用费计算**：`设备使用费 = 未税单价 × 设备使用费比例 / 100`，比例从公司配置中获取（device_usage_fee_ratio），默认100。

## 附录：库存计算逻辑

```
可用库存(avail) = 在库数量(stock) - 已锁定/已分配数量

在库数量(stock) = SUM(入库数量) - SUM(出库数量)
  - 入库来源：调拨入库、其他入库、样品入库、夹治具入库、采购入库
  - 出库来源：调拨出库、其他出库、销售出库、盘亏出库

在途数量(transit) = 已出库但未入库确认的数量

库存维度：material_id + stock_id(仓库) + space_id(仓位)
```
