### 1.8 机器人数据结算流程（Kafka → 日结 → 月结）

```
上位机上报生产数据 → POST /api/admin/robot_manage/add-data
  ├─ 写入 r_robot_data（含 OEE/产能/良品率等指标）
  ├─ 判断 robot_status != 调试中 && key_robot == 1
  │   └─ 推送 robot_data_id 到 Kafka Topic（robot_data_settle）
  └─ 调试状态或非关键机器人 → background_operation = -2，不参与结算

Kafka 消费者（RobotDataQueue / RobotDataQueueV2 定时任务）
  ├─ 消费 robot_data_id
  ├─ 查询 r_robot_data 获取生产数据
  ├─ 关联客户结算配置（计费模式、阶梯价格、分润比例）
  ├─ 写入 r_robot_data_settle（含公司收益、业务员/运维/项目经理分润）
  └─ 写入 r_robot_data_work_station（工位维度产量）

日结（DailySettlement）
  ├─ 汇总当日 r_robot_data_settle 数据
  └─ 生成日结核签记录

月结（MonthSettlement）
  ├─ 汇总当月日结数据
  └─ 生成月结核签记录
```

### 5.2 警报处理流程

```
1. 触发检测
   ├─ 自动检测：listenRobotHeartbeat() 每分钟轮询机器人心跳
   │   └─ 心跳超时/状态异常 → 自动生成警报记录
   └─ 手动上报：saveWarning() 人工录入警报

2. 分级推送（消息队列 RobotWarningQueue）
   ├─ Level 1：立即推送企业微信小程序通知给部门负责人
   │   └─ 内容：客户、机器人编号、故障等级、故障代码、工位、工位坐标
   ├─ 致命级别额外操作：
   │   └─ 通过腾讯云语音消息（VMS）拨打负责人电话
   └─ Level 2~3：延迟30分钟逐级向上级部门负责人推送
       └─ 最多推送3级（level ≤ 3）

3. 人工处理
   ├─ solveWarning() 记录处理方法、处理时长、附件
   └─ status 更新为 2（已处理）

4. 统计分析
   ├─ countTimeWheel()：24H全时段统计（时间轮）
   ├─ errorCount()：故障统计
   └─ errorTrend()：故障趋势分析
```

## 附录：日志表

### r_log_robot_company_change（公司变更日志）

记录机器人所属公司的变更历史，含 robot_id、robot_no、company_id、start_time、end_time。

### r_log_robot_customer_ground_change（客户场地变更日志）

记录机器人部署的客户/场地变更历史，含 robot_id、robot_no、customer_id、customer_ground_id、work_station_id、start_time、end_time。

### r_log_robot_operation（机器人操作日志）

记录机器人运行状态变化，含 robot_no、robot_arm_sn、timestamp、robot_status_type（running/stop）、robot_status_detail、company_id、customer_id。

### r_view_robot_info_statis（机器人信息统计视图）

数据库视图，汇总机器人部署信息：customer_name、robot_no、robot_status、province/city/town/area、work_station_name、industry、workmanship_type 等字段，用于统计看板。
