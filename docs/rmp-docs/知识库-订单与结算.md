# RMP 订单与结算模块知识库

> 数据来源：`rmp_tables.json` 表结构 + `app/admin/controllers/` 控制器 + `nnd-robot/src/views/` 前端页面
> 覆盖模块：上岗单管理、日结核签、月结核签、销售订单、销售退货单
> 业务定位：机器人数据 → 日结 → 月结 → 财务对账 的全链路结算闭环

---

## 一、结算流程链路总览

```
┌─────────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  上岗单      │ →  │  机器人数据   │ →  │  日结核签     │ →  │  月结核签     │ →  │  财务对账     │
│ (合同/计费)  │    │ (系统采集)    │    │ (运维录入)    │    │ (汇总/拆分)   │    │ (审核/收入)   │
└─────────────┘    └──────────────┘    └──────────────┘    └──────────────┘    └──────────────┘
   r_post_statement   ES 采集           r_daily_settlement  r_month_settlement  r_financial_reconciliation
                                         (type=1 运维)       (含单价/收入)        (客户银行账户)
                                         (type=2 财务)
```

**链路说明：**
1. **上岗单**（`r_post_statement` + 工作许可证）锁定客户、工位、计费方案（计时/计件/UPH），是结算的合同依据。
2. **机器人系统数据**由设备端实时采集，落入 ES 索引，按"工位 + 机器人 + 产品 + 日期"维度组织。
3. **日结核签**：运维每日按工位/机器人录入核签工时、件数、附件（`r_daily_settlement.type=1`）；财务侧审核/退回（`type=2`）。状态机：待核签 → 已核签 → 待审核 → 已审核（可被退回）。
4. **月结核签**：按对账周期（`settle_month` YYYY-MM 或 `settle_period_start/end`）将日结汇总，并计算单价、设备租赁费、技术服务费、未含税金额、本月收入（`r_month_settlement`）。
5. **财务对账**：`r_financial_reconciliation` 维护客户银行账户（户名/开户行/账号），配合月结生成对账单与收款流水。

## 二、计费方案类型

计费方案存储在 `r_post_statement_work_permit.fee_json`（旧）/ `new_fee_json`（新），并由 `r_daily_settlement.settle_mode` 与 `r_month_settlement.settle_mode` 标记每条结算记录的计费模式：

| settle_mode | 名称 | 说明 | 关键字段 |
|---|---|---|---|
| 1 | 计时 | 按核签工时（`settle_hour`）× 单价计费 | `system_hour` 系统工时、`settle_hour` 核签工时 |
| 2 | 计费/计件 | 按实际产能件数（`actual_output`）× 单价计费 | `actual_output` 件数 |
| 3 | UPH 计费 | 按 UPH（每小时产能）阶梯计费 | `settle_section_value` UPH 阈值 |

**保底设置**（`minimum_json`）：
- `check_man_hour` 保底工时开关（0未选/1已选），`man_hour` / `working_hours_6` / `working_hours_7` 保底工时值。
- `check_sum` 保底金额开关，`sum` 保底金额值。

> 新旧字段并存：`fee_json` 为旧版计费设置，`new_fee_json` 为新版；上线后以 `new_fee_json` 为准。

## 三、上岗单管理

### 3.1 业务说明

上岗单是机器人驻场服务的合同载体，承载客户、客户经理、签订/到期日期、试运行标志、计费方案、设备清单、部署计划单、部署验收单等全生命周期信息。一条上岗单可关联多个工位（`r_post_statement_work_permit_work_station`），每个工位有独立的验收状态。

**主表状态机**（`r_post_statement.status`）：

| status | 含义 |
|---|---|
| 1 | 草稿 |
| 2 | 草稿待审核 |
| 3 | 方案 |
| 4 | 待审核 |
| 5 | 部署准备 |
| 6 | 部分就绪 |
| 7 | 全就绪 |
| 8 | 终止 |

**工作许可证审批状态**（`r_post_statement_work_permit`）：
- `status`：1草稿 / 2待审批 / 3审批中 / 4已审批 / 5反审批
- `flow_status`：1草稿 / 2待审批 / 3审批通过 / 4反审批（与工作流引擎 `flow_id` 联动）

---

### r_post_statement（上岗单主表，388 行）

**用途**：记录上岗单编号、客户、客户经理、签订/到期时间、试运行标志与生命周期状态。

**核心字段**：
- `post_statement_no` varchar(32) 上岗单编号（索引 `idx_post_statement_no`）
- `company_id` / `customer_id` / `cpm_user_id`（客户经理）公司/客户/经理 ID
- `file_archives_id` 上岗单档案 ID（指向附件）
- `sign_time` / `due_time` 签订日期 / 到期时间（int unsigned 时间戳）
- `try_operation` tinyint 试运行（1是 / -1否）
- `status` tinyint 生命周期状态（见上表，索引 `idx_status`）

**索引**：PRIMARY(id)、idx_post_statement_no、idx_customer_id、idx_cpm_user_id、idx_status

**关联**：`customer_id` → 客户主表；`cpm_user_id` → 用户表；工作许可证 → `r_post_statement_work_permit`

---

### r_post_statement_work_permit（上岗单工作许可证，256 行）

**用途**：存储上岗单的工作许可证详情，含双方联系人、计费方案（fee_json/new_fee_json）、保底设置（minimum_json）、部署计划单（deploy_plan_*）、部署验收单（deploy_check_*）。

**核心字段**：
- `work_station_id` int（弃用，改用关联表）
- `sign_date` date 签订日期
- 双方联系人：`contact_user_id` / `contact_mobile` / `fax`（我方）；`customer_contact_name` / `customer_contact_mobile` / `customer_fixed_line`（客户）
- `detail` json 工位方案产品详情
- 计费：`fee_json` text（旧计费设置）、`new_fee_json` text（新计费设置）、`minimum_json` text（保底设置）
- 保底：`check_man_hour` / `man_hour` / `working_hours_6` / `working_hours_7`（保底工时）；`check_sum` / `sum`（保底金额）
- 部署计划单：`deploy_plan_produce_json` 生产计划、`deploy_plan_produce_date` 生产计划日期、`deploy_plan_slotting_date` 进场日期、`deploy_plan_introduce` 说明、`deploy_plan_file` 部署计划单附件
- 部署验收单：`deploy_check_date` 验收日期、`deploy_check_content` 验收内容、`deploy_check_status`（1合格/2不合格）、`deploy_check_introduce` 说明、`deploy_check_file` 部署验收单附件
- `status` / `flow_status` / `flow_id` / `current_flow_node` 审批状态与工作流
- `approve_time` 审批通过时间
- 权限范围：`range_user_read/write`、`range_role_read/write`、`range_department`、`range_company`

**索引**：PRIMARY(id)、idx_work_station_id

---

### r_post_statement_work_permit_work_station（上岗单工位表，298 行）

**用途**：上岗单工作许可证下的工位明细，每个工位独立记录验收信息。

**核心字段**：
- `post_statement_work_permit_id` int 工作许可证 ID
- `work_station_id` int unsigned 工位 ID
- `deploy_product` varchar(100) 工位产品
- `deploy_check_date` 验收日期、`deploy_check_status`（1合格/2不合格）
- `deploy_check_content` 验收内容、`deploy_check_introduce` 不合格说明
- `deploy_check_file` 部署验收单附件

**索引**：PRIMARY(id)

## 四、日结核签

### 4.1 业务说明

日结核签按"工位 + 机器人 + 产品 + 日期"维度，由运维录入核签工时/件数，财务审核。系统工时来自机器人采集，核签工时为人工确认值，二者差异用于异常分析。

**状态机**（`r_daily_settlement.status`）：

| status | 含义 | 触发动作 |
|---|---|---|
| 1 | 待核签 | 系统自动生成 |
| 2 | 已核签 | 运维保存核签（`type=1`） |
| 3 | 待审核 | 运维批量提交 |
| 4 | 已审核 | 财务审核通过（`type=2`） |
| 5 | 被退回 | 财务退回（`finance-refund`） |
| 6 | 终止 | 手动终止 |

**双角色机制**：`type=1` 运维侧（录入/核签）、`type=2` 财务侧（审核/退回）。

---

### r_daily_settlement（日结主表）

**用途**：存储每日按工位/机器人/产品的核签记录，含系统工时、核签工时、件数、计费模式、对账周期。

**核心字段**：
- `work_station_id` / `robot_id` / `product_id` 工位/机器人/产品（均有索引）
- `system_hour` decimal(10,2) 系统工时（设备采集）
- `actual_output` int 件数
- `settle_hour` decimal(10,2) 核签工时（人工确认）
- `attachment` varchar(200) 核签文件
- `settle_mode` tinyint 计费方式（1计时/2计费/3 UPH计费）
- `settle_section_value` decimal(10,2) UPH 值
- `settle_month` varchar(7) 对账周期（YYYY-MM，如 2026-08）
- `settle_period_start` / `settle_period_end` date 对账周期起止
- `status` tinyint 状态（见上表）
- `flow_id` / `current_flow_node` 工作流
- `type` tinyint 类型（1运维/2财务）
- `gmt_time` date 核签日期
- 权限范围：`range_user_read/write`、`range_role_read/write`、`range_department`、`range_company`

---

### r_settle_daily（日结明细-按时间段，0 行）

**用途**：按时间段（time_quantum）拆分的日结明细，支持计时/计件两种模式与审核流。当前数据为空，属预留/历史结构。

**核心字段**：
- `time_quantum_id` int 时间段 ID（索引，→ `r_settle_daily_time_quantum`）
- `work_station_id` / `robot_id` / `robot_no` 工位/机器人
- `settle_mode` tinyint 结算模式（1计时/2计件）
- `settle_price` decimal(7,4) 计费价格
- `review_capacity` int 核签产能（计时=实际生产时间，计件=实际产能）
- `review_file_id` / `review_user_id` 核签文件/审核人
- `status` tinyint（0未处理/1审核通过/2反审核/-1审核不通过）

**索引**：PRIMARY、idx_time_quantum_id、idx_work_station_id、idx_robot_id、idx_robot_no、idx_settle_mode

---

### r_settle_daily_time_quantum（结算时间段，0 行）

**用途**：定义结算时间段（开始/结束时间），绑定公司、客户、场地与场地负责人。

**核心字段**：
- `start_time` / `end_time` int unsigned 开始/结束时间
- `company_id` / `customer_id` / `customer_ground_id` 公司/客户/场地（均有索引）
- `operator_user_ids` varchar(255) 场地负责人（逗号分隔）
- `log_user_id` / `last_editor_id` / `last_edit_time` 操作记录

**索引**：PRIMARY、idx_company_id、idx_customer_id、idx_customer_ground_id、idx_last_editor_id、idx_log_user_id

## 五、月结核签

### 5.1 业务说明

月结将对账周期内的日结数据按"客户 + 工位 + 机器人 + 产品"汇总，计算单价、设备租赁费、技术服务费，得出未含税金额与本月收入。月结支持按工位组（`work_group_id`）聚合查看。

**状态机**（`r_month_settlement.status`）：与日结一致（1待核签/2已核签/3待审核/4已审核/5被退回/6终止）。

---

### r_month_settlement（月结主表）

**用途**：按月汇总的结算记录，含金额计算字段，是财务对账的核心数据源。

**核心字段**：
- `customer_id` / `company_id` / `work_station_id` / `work_group_id` / `robot_id` / `product_id` 维度
- `system_hour` / `actual_output` / `settle_hour` 工时与件数（汇总值）
- `attachment` 核签文件
- `settle_mode` / `settle_section_value` 计费方式与 UPH 值
- `status` / `flow_id` / `current_flow_node` 状态与工作流
- **金额计算**：
  - `unit_price` decimal(10,2) 单价
  - `device_price` decimal(10,2) 设备租赁费
  - `service_price` decimal(10,2) 技术服务费
  - `not_tax_income` decimal(10,2) 未含税总金额
  - `settle_income` decimal(10,2) 本月收入
- `gmt_time` varchar(10) 核签月份
- `settle_period_start` / `settle_period_end` date 对账周期起止
- 权限范围字段同日结

**索引**：PRIMARY、idx_customer_id、idx_work_station_id

## 七、销售订单

### 7.1 业务说明

销售订单记录向客户销售产品（机器人/设备/物料）的单据，支持手动创建与工位方案生成两种来源。订单审核后可生成销售出库单（`is_outbound` 标记），出库后支持销售退货。物料明细支持含税/不含税双价格体系与客户产品编号映射。

---

### r_sale_order（销售订单主表，52 行）

**用途**：记录销售订单编号、客户、销售日期、来源、出库状态与客户 PO 号。

**核心字段**：
- `name` varchar(32) 订单名称
- `sale_no` varchar(32) 订单编号（索引 `idx_sale_no`）
- `source` varchar(32) 订单来源（`common` 手动创建；另有工位方案来源）
- `contact` varchar(32) 关联 ID/编号（如工位方案编号，索引 `idx_contact`）
- `sale_time` date 销售日期
- `customer_id` / `sale_user_id` 客户/销售人员

## 八、销售退货单

### 8.1 业务说明

销售退货单针对已出库的销售订单发起退货，关联销售订单与销售出库单，明细记录退货物料、数量、入库仓库/仓位、价格。退货单走审批流（草稿 → 待审批 → 已审批），支持反审批。仅财务与销售总监角色可见价格。

**状态机**（`r_sale_order_return.status`）：1草稿 / 2待审批 / 3已审批。

---

### r_sale_order_return（销售退货单主表，44 行）

**用途**：记录退货单编号、日期、原因、关联销售订单/出库单、收货人信息与审批流。

**核心字段**：
- `order_no` varchar(50) 单据编号（索引 `idx_order_no`）
- `submit_date` date 单据日期
- `reason` / `reason_text` varchar(200) 退货原因（编码 / 文本）
- `desc` / `remark` 备注字段
- `status` tinyint 状态（1草稿/2待审批/3已审批）
- `flow_id` / `current_flow_node` 工作流
- `customer_id` / `sale_order_id` / `outbound_order_id` 客户/销售订单/销售出库单
- `receiver_id` / `receiver_phone` / `receiver_name` / `receive_address` 收货人信息
- 权限范围字段（同上岗单）

**索引**：PRIMARY、idx_order_no

## 十、权限与数据范围说明

所有结算相关表均内置四级数据范围字段（与 RBAC 联动）：

| 字段 | 含义 |
|---|---|
| `range_user_read` / `range_user_write` | 只读/读写用户 ID（逗号分隔） |
| `range_role_read` / `range_role_write` | 只读/读写角色 ID |
| `range_department` | 可读部门 ID |
| `range_company` | 可读公司 ID |
| `company_id` | 数据所属公司（多租户隔离） |

- **总公司**（`Company::HEAD_COMPANY_ID`）可查看所有公司数据（控制器中 `company_id` 置 0 放开）。
- **销售退货价格**仅"财务""销售总监"角色可见（`SaleOrderReturnController::list` 中 `has_auth_show_price` 判断）。
- 日结/月结的财务审核接口（`finance-audit`/`finance-refund`）需财务角色权限。
