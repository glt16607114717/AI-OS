# RMP 财务与看板报表模块 知识库

> 覆盖范围：财务管理（物料收发明细、付款单、期初库存、关账与对账）、看板（BI 中心、客户看板、工作台、模拟卡位、排名报表）、数据看板/统计（公司经营月报、角色统计）。
> 数据源：`rmp_tables.json`、`rmp-api/app/admin/controllers/{finance,charts}`、`StatisticsController`、`chartsapi`（图表后端）、`charts`（图表前端）。

---

## 一、财务管理域

财务管理域围绕"物料成本"与"对外付款"两条主线展开，对应 `rmp-api/app/admin/controllers/finance/` 目录下的三个控制器：`MaterialCostController`、`PaymentOrderController`、`InitialStockController`。数据上以"期初库存 + 收发流水"驱动移动加权平均成本，并通过"付款单 + 关账期间"形成对外结算闭环。

### 1.1 业务概览与成本核算逻辑

RMP 的物料成本核算采用"移动加权平均法"，核心数据链为：期初库存（`r_financial_material_initial_stock`）→ 收发流水（`r_material_cost_detail_log`）→ 关账期间（`r_financial_closing_period`）。其中收发流水表是最关键的台账，每一次入库/出库动作都会追加一条明细，并同步刷新物料的平均成本、期末数量和期末成本。

付款单（`r_finance_payment_order`）独立于物料成本，用于记录对外付款（货款、服务款、工程款等），通过工作流审批后形成已审批单据；对账信息（`r_financial_reconciliation`）维护客户/公司的银行账户档案，供付款与收款调用。

分润配置（`r_commission_config`）虽然不在 finance 控制器目录，但属于财务结算的扩展配置，用于按组织树设置分润比例。

### 1.2 r_material_cost_detail_log（物料收发明细日志）

**用途**：物料收发流水台账，是成本核算与财务收发报表的核心数据源。每一笔出入库业务（调拨、采购、销售、生产领退料、模拟领退料、部署/取消部署等）都会写入一条记录，并维护物料的平均成本和期末库存。

**核心字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | int | 主键 |
| `order_id` / `order_no` | int / varchar(50) | 单据 ID 与单据编号，关联出入库原始单据 |
| `order_type` | tinyint | 单据类型：1=调拨出库，2=其他出库，3=盘点出库，4=销售出库，5=生产领料，6=采购退货，7=采购入库，8=调拨入库，9=设备入库，10=盘点入库，11=其它入库，12=生产退料，13=模拟领料，14=模拟退料 |
| `material_id` / `product_no` / `serial_no` | - | 物料 id / 物料编码 / 批次号 |
| `is_product` | tinyint | 是否量产（1量产 2非量产） |
| `stock_id` / `space_id` | int | 变化仓库 id / 变化仓位 id |
| `initial_num` | decimal(10,2) | 期初数量 |
| `change_num` | decimal(10,2) | 变动数量（入库正、出库负） |
| `avg_cost` | decimal(14,4) | 平均成本（未税单价） |
| `change_cost` | decimal(12,2) | 本次变化总成本 |
| `period_num` | decimal(10,2) | 期末数量 |
| `period_avg_cost` | decimal(14,4) | 期末平均成本 |
| `period_total_cost` | decimal(12,2) | 期末总成本 |
| `initial_data` | tinyint | 是否期初数据（0否 1是） |
| `add_by_review` / `review_order_no` / `review_order_type` | - | 反审相关：是否反审新增、反审单据编号、反审单据类型 |
| `desc` | varchar(255) | 备注 |
| `is_delete` / `gmt_modified` / `gmt_create` | - | 通用字段 |

**索引**：PRIMARY(`id`)、`idx_material_id`、`idx_product_no`、`idx_serial_no`、`idx_order_no`、`idx_order_type`。当前数据量约 2146 行。

**关联关系**：通过 `order_no` 关联各类出入库原始单据；通过 `material_id`/`product_no`/`serial_no` 关联物料主档与期初库存表 `r_financial_material_initial_stock`。

**API 接口**：
- `GET /api/admin/finance/material-cost`：物料收发明细列表，支持按单据号、单据类型、物料编码、批次号、仓库名、时间区间筛选。
- `GET /api/admin/finance/material-cost-bill-type`：返回 19 种单据类型（含模拟领料-入库/出库、取消部署、部署等扩展类型）的字典。

### 1.3 r_financial_material_initial_stock（期初库存）

**用途**：物料期初库存台账，用于"移动加权平均法"的初始成本基线，并通过 Excel 导入批量初始化。

**核心字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | int | 主键 |
| `material_id` | int unsigned | 物料 id |
| `product_no` | varchar(30) | 物料编码 |
| `serial_no` | varchar(100) | 序列号/批次号 |
| `is_product` | tinyint | 是否量产（1量产 2非量产） |
| `initial_num` | decimal(20,2) | 期初数量 |
| `avg_cost` | decimal(20,4) | 单位成本 |
| `total_cost` | decimal(32,2) | 期初总价 = 数量 × 单位成本 |
| `creator_user_id` | int | 创建者 |
| `is_delete` / `gmt_modified` / `gmt_create` | - | 通用字段 |

**索引**：PRIMARY、`idx_material_id`、`idx_product_no`、`idx_serial_no`、`idx_is_product`。当前数据量约 1050 行。

**API 接口**：
- `GET /api/admin/finance/initial-stock/list`：期初库存列表。
- `POST /api/admin/finance/initial-stock/import`：Excel 批量导入（列头：序号、物料编码、识别码、批次号、数量、单位成本，单次限 500 行）。
- `POST /api/admin/finance/initial-stock/save`：保存导入解析后的数据。
- `POST /api/admin/finance/initial-stock/del`：软删除（按 id 批量）。
- `GET /api/admin/finance/initial-stock/material-select-list`：物料编码下拉。
- `GET /api/admin/finance/initial-stock/material-serial-no`：物料批次号下拉。

### 1.4 r_finance_payment_order（付款单）

**用途**：对外付款单据，支持草稿→待审批→审批中→已审批的工作流，并内置四级数据权限（用户/角色/部门/公司 可读可写）。

**核心字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | int | 主键 |
| `payment_no` | varchar(50) | 付款单号（唯一索引） |
| `payment_type` | varchar(20) | 付款类型：货款、服务款、工程款、水电费、租金、设备款、往来款、押金、其他 |
| `site_area` | decimal(10,2) | 场地面积 |
| `payment_amount` | decimal(10,3) | 付款金额 |
| `payment_method` | varchar(20) | 付款方式：银行卡、现金、汇票、电汇、贷记、支票、其他 |
| `payment_date` | date | 付款日期 |
| `payee_name` / `bank_account` / `bank_name` | - | 收款人全称 / 银行账号 / 开户行 |
| `remark` / `attachment` | - | 备注说明 / 附件 |
| `status` | tinyint | 状态：1草稿，2待审批，3审批中，4已审批 |
| `flow_id` / `current_flow_node` | - | 工作流 id / 当前流程节点 |
| `company_id` | int unsigned | 公司 id |
| `range_user_read` / `range_user_write` | varchar(1000) | 只读/读写用户 id 列表（逗号分隔） |
| `range_role_read` / `range_role_write` | varchar(1000) | 只读/读写角色 id 列表 |
| `range_department` / `range_company` | varchar(1000) | 可读部门/公司 id 列表 |
| `creator_user_id` / `is_delete` / `gmt_modified` / `gmt_create` | - | 通用字段 |

**索引**：PRIMARY(`id`)、唯一索引 `payment_no`。当前数据量约 37 行。

**API 接口**：
- `GET /api/admin/finance/payment-order/list`：付款单列表。
- `POST /api/admin/finance/payment-order/save`：保存（校验金额、付款方式、收款人等）。
- `GET /api/admin/finance/payment-order/detail`：详情。
- `GET /api/admin/finance/payment-order/new-no`：取最新编号。
- `PUT /api/admin/finance/payment-order/update-status`：修改状态（status 必须 ∈ 1/2/3/4）。
- `POST /api/admin/finance/payment-order/del`：删除单据。

### 1.5 r_financial_closing_period / r_financial_reconciliation（关账与对账）

**r_financial_closing_period（关账期间）**：记录按"公司 + 关账年月 + 单据类型"维度的关账动作，`document_ids` 字段以逗号分隔存储被关账的单据 ID。索引采用 `(company_id, document_type, closing_month)` 联合索引以加速查询。

**r_financial_reconciliation（对账信息）**：维护"公司 + 客户"维度的银行账户档案，字段含 `account_name`(户名)、`bank_name`(开户行)、`bank_account`(银行账户)，支持排序（`sort`）。当前数据量约 56 行，供付款单与收款单据调用。

### 1.6 r_commission_config（分润配置）

**用途**：按组织树配置分润比例，用于结算域的分润计算。

**核心字段**：`organization_code`(组织代码)、`parent_organization_code`(父级)、`relation_chain`(关系链，最长 2000 字符，按组织代码拼接)、`commission_type`(分润类型 tinyint)、`commission_data`(分润数据 decimal(5,2))。索引含 `idx_organization_code`、`idx_parent_organization_code`。

## 二、看板与图表域（chartsapi + charts 前端）

看板域是 RMP 的数据可视化核心，采用"前后端分离 + 独立图表服务"架构：
- **图表后端**：独立项目 `D:\wwwroot\chartsapi`（ThinkPHP 6），提供看板配置、图表数据查询、权限管理等 API。
- **图表前端**：独立项目 `D:\wwwroot\charts`（Vue 3 + Vite），承载 BI 中心、客户看板、个人工作台三大场景。
- **主项目 rmp-api**：在 `app/admin/controllers/charts/` 下保留少量"嵌入式"图表接口（模拟卡位、客户排名、交付运维报表、工位报表），与 chartsapi 形成互补。

### 2.1 看板配置体系（board / group / permission）

看板配置采用"图表 → 分组 → 权限"三层模型，同时支持 BI 中心（bulletin）、客户看板（customer）、工作台（workbench）三套独立体系，复用相同的设计模式。

#### 2.1.1 r_charts_board（看板图表定义）

**用途**：图表元数据定义表，描述每个图表的名称、类型、前端组件标识、适用场景。当前约 108 个图表。

**核心字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | int | 主键 |
| `name` | varchar(50) | 图表名称 |
| `type` | tinyint | 数据类别（见数据字典 `charts_type`） |
| `page_module` | varchar(50) | 前端组件标识（对应 charts 前端的 vue 文件） |
| `remark` / `preview` | - | 备注 / 预览图 |
| `status` | tinyint | 状态：1启用 2停用 |
| `is_customer_board` | tinyint | 是否可设为客户看板（1是 2否） |
| `is_workbench_board` | tinyint | 是否工作台看板（1是 2否） |
| `show_scene` | varchar(60) | 展示场景：1个人BI中心 / 2工作台 / 3客户看板 |
| `delivery_work_order_id` | int | 工单 id（部分交付类图表关联） |
| `iteration_develop_time` | datetime | 迭代开发完成时间 |

**索引**：PRIMARY、`idx_name`。

#### 2.1.2 r_charts_group / r_charts_group_to_board（分组与关联）

**r_charts_group（看板分组）**：用户/客户的看板分组，约 1354 行。核心字段：`name`(分组名)、`customer_id`(客户 id，客户看板专用)、`is_investor`(是否经营看板)、`type`(1默认 2非默认)、`link`/`password`(分享链接与密码)、`is_contain_header`(分享是否含页头)、`refresh_time`(刷新时间)、`layout`(布局 JSON)、`bind_company_id`(绑定公司 id)。

**r_charts_group_to_board（分组-图表关联）**：约 12837 行，是多对多关联表。核心字段：`group_id`、`board_id`、`filter_search`(该图表在该分组下的搜索条件 JSON)、`copy_from`(复制来源)、`extension`(扩展字段 longtext)。

#### 2.1.3 r_chart_flexible_design（看板自定义布局）

**用途**：存储用户对某个分组的自定义拖拽布局（flexible 字段为 longtext JSON），按 `(group_id, user_id, page_module)` 定位。

#### 2.1.4 权限表族

- **r_charts_role_permission_chart**：角色-图表权限（约 10891 行），字段 `role_id`、`board_id`、`is_default`(是否默认显示)。
- **r_charts_role_permission_small_chart**：小看板角色权限（约 9774 行）。
- **r_charts_workbench_role_permission**：工作台角色权限。

### 2.2 工作台体系（workbench）

工作台是独立于 BI 中心的一套"个人/角色工作台"体系，表结构对标看板体系：
- **r_charts_workbench_group**：工作台分组（约 242 行），含 `name`、`sort`、`layout`、`refresh_time`、`default`(是否默认)、`bind_company_id`。
- **r_charts_workbench_group_to_board**：工作台分组-图表关联（约 676 行），结构同 `r_charts_group_to_board`。
- **r_charts_workbench_flexible_design**：工作台自定义布局（约 149 行），含 `drag_position`(需求列表位置)。
- **r_charts_workbench_button**：工作台按钮/权限项定义（约 11 行），字段含 `code`(权限组标识)、`type`(1按钮 2权限)、`behavior`、`permission_platform`(PC)、`url`(前端路由)、`path`(后端路由)、各端负责人 id。

### 2.3 小看板体系（small charts）

- **r_charts_small_charts_board**：小看板图表定义，字段含 `name`、`type`(数据字典 `small_charts_type`)、`page_module`(接口标识)、`unit`(单位)、`is_customer_board`。
- **r_charts_small_charts_group_board**：小看板分组-图表关联。

### 2.4 看板数据快照表族（统计类）

这一组表是 chartsapi 定时任务（见 `command/` 目录的 `NewBoardRecord`、`MonthNewBoardRecord` 等）生成的数据快照，用于趋势图与排名看板，避免实时聚合大表。

#### 2.4.1 r_charts_daily_customer_deploy（每日客户部署快照）

**用途**：按"客户 + 日期"维度的工位部署快照，约 55906 行。字段：`customer_id`、`company_id`、`deploy_station_num`(已部署工位数)、`ready_station_num`(已就绪)、`not_ready_station_num`(未就绪)、`station_num`(工位总数)、`status`(客户状态)、`gmt_time`(日期)。索引含 `idx_customer_id`、`idx_gmt_time`。

#### 2.4.2 r_charts_daily_work_station_deploy（每日工位部署快照）

**用途**：按"工位 + 日期"维度的机器人上岗快照，约 8992 行。字段：`customer_id`、`work_station_id`、`deploy_num`(上岗机器人数)、`total_num`(总机器人数)、`deploy_rate`(上岗率)、`gmt_time`、`week`(星期几)、`company_id`。

#### 2.4.3 r_charts_daily_customer_work_hour / r_charts_month_customer_work_hour（客户工时）

**r_charts_daily_customer_work_hour**：按"客户 + 工位 + 日期"的工时明细。字段：`time_of_data`(日期)、`customer_id`、`work_station_id`、`man_hour`(工时)、`actual_output`(产能)、`exception_waiting_time`(异常待料时间)。

**r_charts_month_customer_work_hour**：按"客户 + 月份"汇总的工时数据。字段：`time_of_data`(月份 varchar(30))、`customer_id`、`man_hour`、`actual_output`、`exception_waiting_time`。索引 `idx_time_company_customer`。

#### 2.4.4 r_charts_robot_deploy_record（机器人上岗记录）

**用途**：按日期的机器人上岗汇总，约 767 行。字段：`deploy_num`(上岗数)、`total_num`(总数)、`deploy_rate`(上岗率)、`gmt_time`、`company_id`。索引 `idx_gmt_time`。

#### 2.4.5 r_charts_month_new_board_record（月度经营看板记录）

**用途**：月度经营看板的核心快照，字段：`deploy_num`(上岗机器人数)、`deploy_rate`(上岗率)、`purpose_num`(累计意向客户)、`arrange_num`(已部署客户)、`station_num`(已就绪工位)、`deploy_station_num`(已部署工位)、`company_id`、`gmt_time`(varchar(20))。

#### 2.4.6 r_charts_month_delivery_maintain_stat（月度交付运维统计）

**用途**：交付运维报表的月度数据源，约 43 行。按"年 + 月"维度存储各类工单/工位 ID 集合（text 字段，逗号分隔），用于计算交付数、退库数、异常退库数等指标。

**核心字段**：`year`、`month`、`actual_deploy_delivery_order_ids`(本月交付工单 id)、`maintain_back_work_station_ids`(本月运维退库工位 id)、`deploy_work_station`(截至本月部署工位 id)、`delivery_question_back`(模拟异常退库工单 id)、`deploy_question_back`(部署异常退库工单 id)、`maintain_question_back`(运维异常退库工位 id)、`maintain_normal_back`(运维正常退库工位 id)、`plan_production_cancel`(计划排产作废工位 id)、`plan_production_bind`(方案已绑定未签上岗单工位 id)。

### 2.7 图表后端（chartsapi）接口总览

图表后端位于 `D:\wwwroot\chartsapi`，路由定义在 `app/admin/route/route.php`，统一前缀 `api/admin`，需登录中间件 `admin_auth`。主要路由分组：

### 2.8 主项目 charts 控制器（嵌入式图表接口）

主项目 `rmp-api/app/admin/controllers/charts/` 下有 4 个控制器，提供与 chartsapi 互补的接口：

**AnalogWorkStationController**（模拟卡位）：
- `GET /api/admin/charts/analog-work-station`：按模拟卡位 id 查询。

**CustomerController**（客户排名与产能）：
- `GET /api/admin/charts/customer-rank-top-ten`：客户综合排名 TOP10（按 `sort_field`/`sort_type` 排序）。
- `GET /api/admin/charts/running-customer-level`：运行中客户等级分布。
- `GET /api/admin/charts/customer-capacity-hours`：客户产能工时明细（按客户/工位/月份）。
- `GET /api/admin/charts/pay-customer-num`：支付客户数量统计。
- `GET /api/admin/charts/terminated-customer`：已终止客户统计。
- `GET /api/admin/charts/running-customer-work-station`：已部署客户/工位数量趋势（按年）。

**ReportController**（交付运维 + 角色统计报表）：
- `GET /api/admin/charts/delivery-maintenance`：交付运维报表（按月份区间 + 公司）。
- `GET /api/admin/charts/delivery-maintenance-export`：交付运维报表导出（异步，预创建下载日志）。
- `GET /api/admin/charts/role-report/statistics`：角色统计报表-头部统计。
- `GET /api/admin/charts/role-report/report-body`：角色统计报表-报表主体（按角色类型/字段/排序/用户状态）。
- `GET /api/admin/charts/role-report/export`：角色统计报表导出-运营状态。
- `GET /api/admin/charts/role-report/export-part2`：角色统计报表导出-按月分组统计表。

**WorkStationController**（工位报表）：
- `GET /api/admin/charts/work-station-report`：工位报表（支持导出类型、正常/异常退料时间、排序、搜索字段）。
- `GET /api/admin/charts/work-station-status-options`：工位状态选项（缓存 1 小时）。

图表前端位于 `D:\wwwroot\charts`（Vue 3 + Vite + UnoCSS），路由极简（仅 `/` Dashboard 和 `/workbench` PersonalWorkbench），实际页面内容由后端配置驱动动态渲染。

## 三、数据看板/统计域（StatisticsController）

统计域位于主项目 `rmp-api/app/admin/controllers/StatisticsController.php`，提供面向角色的统计概览与公司经营月报。

### 3.1 角色统计概览

**接口**：`GET /api/admin/statistics-manage/data?type=salesman|operator`

根据当前登录用户的角色类型，返回对应的统计概览数据：
- `type=salesman`：调用 `BusinessRepository::salesmanStatistics($user_id)`，返回业务员维度的客户、订单、收入等概览。
- `type=operator`：调用 `OperationRepository::operatorStatistics($user_id)`，返回运营人员维度的工位、机器人、稼动率等概览。

> 代码中保留了 `公司领导`、`开发` 两个注释分支，说明曾支持更多角色类型，当前仅启用业务员与运营两类。

### 3.2 公司经营月报

**接口**：`GET /api/admin/statistics-manage/company-monthly-report?start_time=`

**数据来源**：`StatisticsRepository::headquartersMonthManageStatistic($company_id, $start_time)`。

**逻辑**：
1. 通过 `CompanyRepository::getCompanyUserContact($user_id)` 获取当前用户所属公司，若为空抛出"无公司信息"异常。
2. `start_time` 缺省时取当前时间（按月统计）。
3. 按公司 id + 时间调用统计仓库，聚合形成月度经营数据（含客户、工位、机器人、工时、稼动率、收入等多维度指标）。

该接口是"公司经营月报"页面的唯一数据源，对应前端 `financialManage/dailyFinancialReview` 或 `monthlyClosingReview` 等视图（具体视图由前端路由配置决定）。

```
财务管理域                          看板/图表域

│   material_          │         │ r_charts_group           │
│   initial_stock      │         │ r_charts_group_to_board  │
│         │            │         │         │                │
│         ▼            │         │         ▼                │

│         ▼            │         │         │                │

│ r_financial_         │         │ 图表前端(charts)         │
│   closing_period     │         │ 150+ vue 组件            │
│                     │         │                          │
│ 付款单               │         │ 统计域                   │
│ r_finance_           │         │ StatisticsController     │
│   payment_order      │         │ - 角色统计               │
│         │            │         │ - 公司经营月报           │
│         ▼            │         │                          │
│ 对账信息             │         │ 分润配置                 │

│   reconciliation     │         │                          │
└─────────────────────┘         └─────────────────────────┘
```

**关键数据流**：
1. **成本流**：期初库存 → 收发流水（移动加权平均）→ 关账（冻结历史）。
2. **付款流**：付款单创建（草稿）→ 工作流审批 → 已审批 → 对账核销。
3. **看板流**：业务系统写入快照表 → chartsapi 聚合查询 → charts 前端渲染。
4. **统计流**：StatisticsController 按角色/公司聚合多源数据，形成月报。
