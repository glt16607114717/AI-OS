# 采购管理模块知识库

> 本文档涵盖 RMP 系统采购管理模块的完整业务流程、数据库表结构、API 接口和前端页面映射。
> 数据源：rmp_tables.json 表结构 + rmp-api 控制器代码 + nnd-robot 前端代码。

## 一、业务全景

### 1.1 完整采购流程链路

```
采购申请单 → 采购订单(主单/子单/明细) → 验货单 → 入库单 → 退货单
     ↓              ↓                     ↓        ↓        ↓
  审批流          审批流                 -       审批流    审批流
     ↓              ↓                     ↓        ↓        ↓
  生成订单      交期管理/付款        良品/次品/特采  库存增加  库存减少
                                                       ↓
                                                  付款申请单 → 审批流
```

### 1.2 审批流状态机（通用）

所有需要审批的单据（申请单、订单、入库单、退货单、付款单、供应商）均使用统一的流程引擎，状态值含义如下：

| 状态值 | 含义     | 说明                         |
|--------|----------|------------------------------|
| 1      | 草稿     | 创建后未提交，可编辑         |
| 2      | 待审批   | 已提交，等待审批人处理       |
| 3      | 审批中   | 流程进行中，多节点流转       |
| 4      | 已审批   | 审批通过，单据生效           |
| 5      | 反审批   | 已审批单据被撤回（部分单据） |

**流程引擎字段**（所有审批单据共有）：
- `flow_id`：绑定的流程模板 ID（关联工作流引擎）
- `current_flow_node`：当前停留的审批节点

### 1.3 数据权限体系（四级范围）

所有采购单据表均包含以下数据权限字段，实现多租户 + 四级数据隔离：

| 字段               | 说明                           |
|--------------------|--------------------------------|
| `company_id`       | 公司 ID（多租户隔离）          |
| `range_user_read`  | 只读用户 ID 列表（逗号分隔）   |
| `range_user_write` | 读写用户 ID 列表               |
| `range_role_read`  | 只读角色 ID 列表               |
| `range_role_write` | 读写角色 ID 列表               |
| `range_department` | 可读部门 ID 列表               |
| `range_company`    | 可读公司 ID 列表               |

### 1.4 采购类型枚举（type 字段）

`r_purchase_order.type` 支持多选，`r_purchase_request.type` 存储类型字符串：
- 1=夹治具，2=定制设备，3=工具，4=模拟设施，5=设备，6=行政办公用品

### 1.5 申请原因枚举（application_purpose）

所有申请类单据共享：
1=正常采购，2=工程设计原因，3=方案变更，4=运维人为损坏，5=程序问题，6=自然损耗，7=客户原因，8=研发改善，9=研发验证

## 二、模块详解

### 模块一：采购申请单（申请→审批流）

#### 业务说明

采购申请单是整个采购流程的起点。需求方（工程师、项目经理或日常采购员）创建申请单，填写所需物料明细，提交后进入审批流程。审批通过后，申请单可作为采购订单的来源数据。

申请单支持两种来源：
- **手动创建**（`submit_way=1`）：人工填写物料需求
- **工位订单生成**（`submit_way=2`）：由工位方案/订单自动触发，携带 `work_order_no`

申请单明细支持逐条状态管理（`updateDetailStatus` 接口），可单独标记明细为启用/停用（status 0/1），便于部分采购场景。

#### 审批流节点

采购申请单审批流节点：申请人提交 → 部门主管审核 → 采购经理审批 →（可选）财务审批 → 审批通过

### 模块二：采购订单（订单→子单→交期管理）

#### 业务说明

采购订单是采购流程的核心单据。一张采购申请单通过后，可按供应商拆分生成多张采购订单。每张订单下按供应商生成**子订单**（`r_purchase_order_child`），子订单下挂具体物料明细（`r_purchase_order_detail`）。

**三层结构：**
```
采购订单（r_purchase_order）
  └── 采购子订单（r_purchase_order_child）—— 按供应商拆分
        └── 采购明细（r_purchase_order_detail）—— 具体物料行
```

采购订单支持交期管理：明细的 `receive_date` 为约定交货日期，修改交期时自动记录到 `r_purchase_order_detail_delivery_history`。

明细的入库状态（`into_status`）实时跟踪：1=未入库、2=部分入库、3=全部入库。

#### 审批流节点

采购订单审批流节点：采购员提交 → 采购主管审核 → 总经理审批（超金额时）→ 审批通过

### 模块四：采购验货单（验货→退货/入库）

#### 业务说明

采购验货单记录到货物料的质量检验结果。验货是入库前的质检环节，每条明细记录采购数量、到货数量、良品数量、次品数量、特采数量和次品率。

验货结果决定后续操作：
- **良品**（`good_num`）→ 进入入库流程
- **次品**（`bad_num`）→ 进入退货流程或协商处理
- **特采**（`special_num`）→ 让步接收，特殊审批后入库

验货明细支持记录实测结果（`result`，逗号分隔多个测量值）、规格公差（`spec_num`/`tolerance`）和量仪信息（`measurer`）。

### 模块六：供应商管理

#### 业务说明

供应商管理是采购体系的基础数据模块。供应商按 18 种分类管理（自动化、机加工、钣金、气动件、IT 类、标准件、机器人等），支持多级审批流程和合作状态管控。

供应商包含完整的财务开票信息（税号、开户行、发票类型）和联系人信息（JSON 结构存储多个联系人）。支持按公司层级查询关联供应商（`getCompanyOwnSupplier` 接口可查询本公司、上级公司、下级公司的供应商）。

### 模块七：付款申请单

#### 业务说明

付款申请单是采购流程的财务终点。基于已审批的采购订单发起付款申请，支持三种金额类型：成交金额（全额付款）、预付款（定金）、尾款。

付款申请关联采购订单编号和子订单编号，记录付款原因、付款方式（现金/转账）、付款账户和付款金额。审批通过后进入财务执行环节。

付款申请还支持记录发票附件（`invoice`）和对账单附件（`statement`），便于财务核账。

#### 审批流节点

付款申请审批流节点：申请人提交 → 部门主管审核 → 财务审核 → 总经理审批（超金额）→ 审批通过 → 财务付款执行
