# PHP 8.0 & ThinkPHP 6 业务研发规范

## 一、项目框架基线

| 项目 | 版本/规范 |
|------|----------|
| 语言 | PHP 8.0+ |
| 框架 | ThinkPHP 6.0.13 |
| Web服务器 | Nginx 1.22 |
| 数据库 | MySQL 5.7+ |
| 存储引擎 | InnoDB |
| 字符集 | utf8mb4_general_ci |
| 表前缀 | `r_` |

## 二、安全、性能与语法红线

- **PHP 8.0 锁定**：强制使用构造器属性提升、`match` 表达式、联合类型、Nullsafe(`?->`)。严禁 PHP 5/7 陈旧语法
- **性能禁区**：严禁在 `foreach` 循环内执行 MySQL 查询、JSON 解析或文件读写等耗时操作（防 N+1 灾难）
- **数据与配置安全**：
  - 严禁拼接原生 SQL；严禁硬编码秘钥（必须走 `env()`/`config()`）
  - 修改 `.env` 文件后，必须同步更新至 `.example.env`
- **异常收口**：严禁留存 `var_dump()`、`die()` 等输出，必须抛出标准 `Exception`

## 三、命名与基础契约

- **基础命名**：类名大驼峰；方法/变量名小驼峰；常量全大写下划线。翻译后的字段固定命名为 `字段_text`
- **状态/类型常量**：禁止硬编码。必须使用类常量表示，且**枚举数字强制从 1 开始**（严禁从 0 开始）
- **注释纪律**：所有生成的接口或方法，强制配备简述逻辑与参数的 PHPDoc 注释

## 四、四层架构约束

所有方法必须包含强类型声明 `declare(strict_types=1);`，代码必须落入以下四层：

### 4.1 Controller（控制层）
- **极简主义**：核心逻辑严禁超 20 行，仅负责接收、调用 Service 转发
- **错误响应**：验证错误抛出时，必须翻译字段的中文名
- **JSON 强契约**：必须遵循 `{"code": 200, "msg": "success", "data": mixed}` 格式。优先调用基础封装（如 `$this->success()`）
- **禁止**：禁止在控制器中编写复杂业务逻辑，禁止直接操作数据库

### 4.2 Validate（校验层）
- 所有外部入参必须通过独立 `Validate` 类拦截验证
- 控制器对入参进行严格检查及验证，可调用技能 `mysql` 查询数据库字段类型辅助验证

### 4.3 Service（服务层）
- 复杂业务流转、跨模块协调、外部 API 调用强制下沉至此
- 复杂业务流程编排、第三方服务调用

### 4.4 Repository（仓库层）
- 封装底层数据库操作，处理数据拼装与事务管理
- 严禁在此处理 HTTP 请求

### 4.5 Model（模型层）
- 所有业务模型必须继承 `BaseModel`。仅保留表关联与修改器，不写业务逻辑
- 模型文件顶部已维护 `@table` + `@property` 表结构注释，查询字段信息时优先从模型类就近获取

### 4.6 控制器路由注释
- 所有控制器方法已维护 `@route` 标签（位于方法 PHPDoc 注释中），调试接口时优先从控制器方法就近获取完整路由地址
- 新增路由时，必须在对应控制器方法的 PHPDoc 中同步添加 `@route` 标签

## 五、标准研发管线（SOP）

编写接口的固定推演路径：
1. `route/` 显式注册路由
2. 建立独立验证器（`Validate`）
3. `Controller` 接收拦截 → `Service` 编排业务 → `Repository` 读写数据 → 组装标准 JSON 返回
4. 在控制器方法 PHPDoc 中添加 `@route` 标签（与路由文件保持同步）

## 六、底线约束

| 类型 | 规则 |
|:-----|:-----|
| **必须** | Controller 只做参数校验与响应组装，业务逻辑放 Service |
| **必须** | 使用依赖注入，禁止 `new` 实例化 Service |
| **必须** | 新增/修改路由时，同步更新控制器方法的 `@route` 标签 |
| **必须** | 新增/修改表字段时，同步更新模型类的 `@property` 注释 |
| **禁止** | 禁止在 Controller 中写 SQL |
