# 服务器 SSH 操作

## 角色定位

通过 SSH 连接远程服务器执行只读操作，用于查看日志、检查配置、部署验证。**严格只读，任何时候禁止写入。**

## 环境寻址

- **绝对路径基准**：所有项目根路径均位于 `/www/wwwroot/`
- **动态获取项目名**：严禁猜测项目服务器目录名称！执行任何 SSH 路径操作前，**必须读取 `docs/server-topology.json`**，获取当前项目在服务器上的真实物理目录名
- **动态获取服务器地址**：SSH 连接地址同样从 `docs/server-topology.json` 的 `servers` 字段读取

---

## SSH 红线

- **绝对只读**：所有 SSH 操作必须是只读（`cat`、`tail`、`ls`、`grep`），**严禁**修改、删除或上传任何文件
- **环境隔离**：开发环境与测试环境严格隔离，禁止跨环境读取或对比
- **范围限制**：SSH 活动范围限制在 `/www/wwwroot/` 下对应项目目录内，严禁进入系统敏感目录

### 条件性操作

- **自主探查**：AI 可自主进行只读 SSH 操作（如查看日志、检查配置），无需用户逐次授权
- **流程内 SSH**：在完整流程的关键节点，SSH 操作随流程执行，不自动跳步

---

## 日志排障管线

排查问题时按以下优先级执行：

1. **本地优先**：检查本地断点日志 `runtime/debug_log/`
2. **SSH 追溯**：读取 `docs/server-topology.json` 获取项目路径后，SSH 查看 `/www/wwwroot/<项目名>/runtime/debug_log/`
3. **框架兜底**：仅在涉及底层报错时，查看框架原生日志 `/www/wwwroot/<项目名>/runtime/log/`

---

## 部署验证

1. **前提**：仅在用户 Git 提交后并明确说"部署验证"时触发
2. **校验**：通过 SSH 执行无损比对（比对关键文件的 hash 或最新 commit），验证本地与服务器文件一致性
3. **结果判定**：文件一致 → 部署成功；不一致 → 检查部署问题
