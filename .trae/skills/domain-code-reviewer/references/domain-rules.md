# 领域审查规则库

本文档汇总各技术领域的专属代码审查规则，供 `<thinking>` 阶段参考。

---

## 算法岗 (AI/ML)

### Tensor 操作

| 规则 | 级别 | 检查点 |
|-----|-----|-------|
| 维度注释 | MUST | 所有 Tensor 操作必须注明输入输出维度 |
| 形状变换 | MUST | reshape/view 操作必须有注释说明目标形状 |
| 广播安全 | SHOULD | 检查广播是否产生非预期结果 |

### 内存管理
| 规则 | 级别 | 检查点 |
|-----|-----|-------|
| 显存释放 | MUST | 训练循环中 loss 使用 `.item()` 断开计算图 |
| 大对象 | MUST | 检查是否存在未释放的大 Tensor |
| 缓存清理 | SHOULD | 定期 `torch.cuda.empty_cache()` |
### 数值稳定性
| 规则 | 级别 | 检查点 |
|-----|-----|-------|
| log 保护 | MUST | `torch.log(x)` 必须加 eps 或使用 log_softmax |
| 除零保护 | MUST | 除法操作必须有 eps 或条件判断 |
| 梯度裁剪 | SHOULD | 推荐使用 `clip_grad_norm_` |
### 可复现性
| 规则 | 级别 | 检查点 |
|-----|-----|-------|
| 随机种子 | SHOULD | 实验代码应设置全局随机种子 |
| 确定性模式 | SHOULD | 关键实验使用 `torch.use_deterministic_algorithms` |

## 后端岗 (Backend)
### 分层规范 (DDD)
| 规则 | 级别 | 检查点 |
|-----|-----|-------|
| Controller 职责 | MUST | 只处理 HTTP 相关逻辑，不包含业务逻辑 |
| Service 职责 | MUST | 业务逻辑封装，不直接操作 HTTP 请求/响应 |
| Repository 职责 | MUST | 只负责数据访问，不包含业务判断 |
| 跨层调用 | MUST | 禁止 Controller 直接调用 Repository |
### 并发安全
| 规则 | 级别 | 检查点 |
|-----|-----|-------|
| 连接池 | MUST | 数据库连接必须使用连接池 |
| 事务范围 | MUST | 事务范围最小化，禁止跨服务事务 |
| 锁粒度 | SHOULD | 检查锁粒度是否合适（行锁/表锁） |
| 缓存穿透 | SHOULD | 检查缓存击穿/雪崩场景 |
### API 设计
| 规则 | 级别 | 检查点 |
|-----|-----|-------|
| 版本控制 | MUST | API 必须有版本号（v1/v2） |
| 错误码规范 | MUST | 使用标准 HTTP 状态码和错误响应格式 |
| 分页规范 | SHOULD | 列表接口必须有分页参数 |
| 幂等性 | SHOULD | 写操作应设计为幂等 |
### 安全
| 规则 | 级别 | 检查点 |
|-----|-----|-------|
| 认证鉴权 | MUST | 所有 API 必须有认证 |
| 权限校验 | MUST | 操作前校验用户权限 |
| 敏感数据 | MUST | 响应中脱敏敏感字段 |
| 日志脱敏 | MUST | 日志禁止记录密码、Token |

### 事务边界
| 规则 | 级别 | 检查点 |
|-----|-----|-------|
| 长事务 | MUST | 禁止超过 5 秒的长事务 |
| 嵌套事务 | MUST | 禁止嵌套事务 |
| 重试机制 | SHOULD | 事务失败应有重试机制 |

## 前端岗 (Frontend)
### 组件规范
| 规则 | 级别 | 检查点 |
|-----|-----|-------|
| 单一职责 | MUST | 一个组件只做一件事 |
| Props 类型 | MUST | 所有 Props 必须有 TypeScript 类型定义 |
| 受控/非受控 | MUST | 明确区分受控和非受控组件 |
| 副作用隔离 | MUST | 副作用在 useEffect 中，不在渲染中 |
### 内存管理
| 规则 | 级别 | 检查点 |
|-----|-----|-------|
| 事件清理 | MUST | useEffect 中订阅的事件必须清理 |
| 定时器清理 | MUST | setTimeout/setInterval 必须有对应的 clearTimeout/clearInterval |
| 闭包陷阱 | SHOULD | 检查 useEffect 依赖数组是否完整 |
| 图片加载 | SHOULD | 大图片使用懒加载和缓存策略 |
### 性能优化
| 规则 | 级别 | 检查点 |
|-----|-----|-------|
| 重渲染 | SHOULD | 检查不必要的重渲染，使用 memo/useMemo/useCallback |
| 虚拟列表 | SHOULD | 长列表使用虚拟滚动 |
| 懒加载 | SHOULD | 路由和大型组件使用懒加载 |
### 安全
| 规则 | 级别 | 检查点 |
|-----|-----|-------|
| XSS 防护 | MUST | 禁止使用 `dangerouslySetInnerHTML`，或必须 sanitize |
| 敏感存储 | MUST | 禁止在 localStorage 存储敏感信息 |
| CSRF | SHOULD | 关键操作需要 CSRF Token |

## 移动端岗 (Mobile - iOS/Android)
### 架构规范
| 规则 | 级别 | 检查点 |
|-----|-----|-------|
| MVVM 遵循 | MUST | View 不直接引用 Model，通过 ViewModel |
| 依赖注入 | SHOULD | 使用 DI 容器或构造函数注入 |
| 单向数据流 | SHOULD | 状态变化可追踪 |
### 内存管理
| 规则 | 级别 | 检查点 |
|-----|-----|-------|
| 循环引用 | MUST | 闭包中使用 `[weak self]` (iOS) 或弱引用 (Android) |
| 资源释放 | MUST | Activity/ViewController 销毁时释放监听器和回调 |
| 图片加载 | SHOULD | 大图片使用缩略图和缓存策略 |
### 生命周期
| 规则 | 级别 | 检查点 |
|-----|-----|-------|
| 状态保存 | MUST | 配置变更时保存状态 |
| 内存警告 | MUST | 响应 didReceiveMemoryWarning 回收资源 |
| 后台任务 | SHOULD | 合理使用后台任务，避免耗电 |

## 测试岗 (QA)
### 测试设计
| 规则 | 级别 | 检查点 |
|-----|-----|-------|
| 边界覆盖 | MUST | 覆盖正常、异常、边界情况 |
| 等价类划分 | SHOULD | 使用等价类划分减少测试用例 |
| 数据驱动 | SHOULD | 参数化测试数据 |
### 代码质量
| 规则 | 级别 | 检查点 |
|-----|-----|-------|
| 命名规范 | MUST | 测试方法名描述测试场景 `test_xxx_when_then` |
| 断言明确 | MUST | 断言信息描述期望值和实际值 |
| Mock 隔离 | SHOULD | 外部依赖使用 Mock 隔离 |
### 自动化
| 规则 | 级别 | 检查点 |
|-----|-----|-------|
| 可重复 | MUST | 测试结果可重复，无随机依赖 |
| 独立性 | MUST | 测试之间相互独立 |
| 清理数据 | SHOULD | 测试后清理测试数据 |

## DevOps 岗
### 基础设施即代码
| 规则 | 级别 | 检查点 |
|-----|-----|-------|
| 状态管理 | MUST | Terraform 状态文件远程存储并加密 |
| 模块化 | SHOULD | 基础设施代码模块化，可复用 |
| 变量化 | SHOULD | 硬编码配置提取为变量 |
### CI/CD
| 规则 | 级别 | 检查点 |
|-----|-----|-------|
| 密钥管理 | MUST | 禁止在代码/日志中暴露密钥，使用 Secrets |
| 幂等性 | MUST | Pipeline 可重复执行，结果一致 |
| 失败处理 | SHOULD | 失败时有明确的错误信息和回滚机制 |
### 安全
| 规则 | 级别 | 检查点 |
|-----|-----|-------|
| 最小权限 | MUST | 服务账号使用最小必要权限 |
| 网络隔离 | SHOULD | 敏感服务部署在私有网络 |
| 审计日志 | SHOULD | 关键操作有审计日志 |

## 通用规则
### 代码质量
| 规则 | 级别 | 检查点 |
|-----|-----|-------|
| 命名语义 | MUST | 变量/函数名表达意图，禁止 a, b, temp |
| 函数长度 | SHOULD | 单个函数不超过 50 行 |
| 注释质量 | SHOULD | 注释解释"为什么"而非"做什么" |
| 重复代码 | SHOULD | DRY 原则，重复代码抽取为函数 |
### 安全通用
| 规则 | 级别 | 检查点 |
|-----|-----|-------|
| 硬编码密钥 | MUST | 禁止硬编码密码、API Key、Token |
| SQL 注入 | MUST | 使用参数化查询，禁止字符串拼接 |
| 输入校验 | MUST | 所有外部输入不可信，必须校验 |
| 日志脱敏 | MUST | 日志禁止记录 PII 和敏感信息 |
### 错误处理
| 规则 | 级别 | 检查点 |
|-----|-----|-------|
| 空指针 | MUST | 访问可能为空的对象前检查 |
| 异常捕获 | MUST | 捕获具体异常，禁止空 catch 块 |
| 资源释放 | MUST | 文件/连接等资源在 finally 或 try-with-resources 中释放 |
