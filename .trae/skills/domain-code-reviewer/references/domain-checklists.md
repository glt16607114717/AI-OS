# 领域审查清单

审查时根据识别的岗位领域，应用对应清单中的审查维度。

---

## 算法岗 (AI/ML)

- [ ] **Tensor 维度**：是否写明了 Tensor 的维度注释？形状变换是否可追溯？
- [ ] **内存管理**：是否存在会导致 OOM 的大对象未释放？
- [ ] **数值稳定性**：是否存在 log(0)、除零、梯度爆炸风险？
- [ ] **可复现性**：是否设置了随机种子？实验是否可复现？
- [ ] **模型序列化**：模型保存/加载是否正确？版本是否兼容？

---

## 后端岗 (Backend)

- [ ] **并发安全**：是否处理了高并发下的数据库连接、缓存穿透？
- [ ] **分层规范**：是否符合 DDD 分层规范？Controller/Service/Repository 边界清晰？
- [ ] **事务边界**：事务范围是否合理？是否存在长事务？
- [ ] **API 契约**：请求/响应结构是否符合 API 规范？
- [ ] **异常处理**：异常是否被正确捕获和转换？是否泄露敏感信息？

---

## 前端岗 (Frontend)

- [ ] **内存泄漏**：是否存在未销毁的事件监听、定时器、订阅？
- [ ] **组件解耦**：是否符合组件解耦规范？Props/State 设计合理？
- [ ] **渲染性能**：是否存在不必要的重渲染？useMemo/useCallback 使用正确？
- [ ] **类型安全**：TypeScript 类型定义是否完整？any 类型是否被滥用？
- [ ] **可访问性**：是否考虑了 a11y（键盘导航、屏幕阅读器）？

---

## 移动端岗 (Mobile - iOS/Android)

- [ ] **生命周期**：是否正确处理 Activity/ViewController 生命周期？
- [ ] **资源释放**：Bitmap、连接、广播是否在适当时机释放？
- [ ] **主线程安全**：耗时操作是否在后台线程？UI 更新是否在主线程？
- [ ] **内存管理**：是否存在内存泄漏（Retain Cycle / Inner Class 泄漏）？

---

## 测试岗 (QA)

- [ ] **测试隔离**：测试用例是否相互独立？是否存在共享状态？
- [ ] **覆盖率**：边界条件、异常路径是否被覆盖？
- [ ] **断言质量**：断言是否足够具体？是否验证了关键业务逻辑？
- [ ] **Mock 合理性**：Mock 是否过度？是否偏离真实行为？

---

## DevOps 岗

- [ ] **幂等性**：部署脚本是否支持重复执行？
- [ ] **回滚能力**：是否设计了回滚机制？
- [ ] **敏感信息**：是否硬编码了密钥、密码？
- [ ] **资源清理**：是否清理了临时资源？
