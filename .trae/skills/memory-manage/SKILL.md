# 本地化记忆管理

## 角色定位

AI 的长期记忆系统，自动记录业务规则和踩坑经验，编码时自动检索避免重复犯错。

## 记忆原则

### 只记录有长期价值的信息

| 类型 | 记录 | 示例 |
|------|------|------|
| ✅ 业务规则 | 状态流转、数据关联、计算规则 | "调拨单审核后自动生成出库单" |
| ✅ 业务约束 | 必填规则、边界条件、限制条件 | "公司ID=2是长安MINI，所有查询必须带company_id" |
| ✅ 踩坑记录 | 不能做的事、容易犯的错 | "r_order表不能用DELETE物理删除，必须用is_delete" |
| ❌ 纯代码错误 | 语法错误、拼写错误 | "少了个分号" |
| ❌ 中间讨论 | 非终极结论的探讨过程 | "我试了三种方案..." |
| ❌ Bug修复过程 | 错误尝试会干扰思维 | "第一次改错了，第二次才对" |
| ❌ 代码实现 | 代码随时可查 | 具体的函数实现 |

**核心：记录"规则是什么"和"什么不能做"，不记录代码和过程。**

## 存储结构

```
D:\wwwroot\ai\ai_cache\memory\
├── daily/                     ← 第1层：每日流水账
│   ├── 2026-04-28.json
│   ├── 2026-04-29.json
│   └── ...
├── weekly/                    ← 第2层：每周汇总
│   ├── 2026-W17.json
│   └── ...
└── archive/                   ← 第3层：最终沉淀
    ├── 2026-04.json           ← 当月规则
    ├── 2026-05.json           ← 下月规则
    ├── ...
    └── pitfalls.json          ← 踩坑记录（一个文件）
```

### 三层流转

| 层级 | 谁写入 | 何时 | 生命周期 |
|------|--------|------|----------|
| daily/ | AI 自动 | 编码过程中实时追加 | 汇总后删除 |
| weekly/ | AI 自动 | 每周五或用户说"汇总记忆"时 | 沉淀后删除 |
| archive/ | 用户手动触发 | 用户说"沉淀记忆"时，AI 从 weekly 提炼 | 永久保留 |

### 每条记忆格式

```json
{
  "id": "mem_001",
  "tags": ["订单", "交付"],
  "content": "调拨单审核后自动生成出库单，出库单状态同步回写",
  "created_at": "2026-04-29"
}
```

- `id`：唯一标识，格式 `mem_NNN`
- `tags`：涉及的业务模块标签，方便过滤
- `content`：记忆内容，简洁明确
- `created_at`：创建日期

**不存** file_path、code_snippet、scenario——代码随时能查，记忆只存逻辑。

## 操作说明

### 自动记录（daily 层）

编码过程中，AI 发现以下信息时自动写入当天的 daily 文件：

1. 发现核心业务规则（状态流转、数据关联、计算公式）
2. 发现重要业务约束（必填规则、边界条件）
3. 踩到坑（发现了不能做的事）

**写入流程**：
```
1. 读取 D:\wwwroot\ai\ai_cache\memory\daily\YYYY-MM-DD.json（不存在则创建 []）
2. 追加新记忆到数组末尾
3. 写回文件
```

**不需要每次操作都写**，只在发现有价值的新信息时才写。

### 自动检索

编码过程中涉及业务逻辑时，AI 自动检索记忆：

**检索流程**（按需，不是每次都全量读）：
```
1. 读 D:\wwwroot\ai\ai_cache\memory\archive\pitfalls.json（全量，量少且都重要）
2. 读 D:\wwwroot\ai\ai_cache\memory\archive\ 中当月和上月的规则文件（按 tags 过滤）
3. 读本周的 D:\wwwroot\ai\ai_cache\memory\weekly\ 文件（如果有）
4. 读今天的 D:\wwwroot\ai\ai_cache\memory\daily\ 文件（如果有）
5. 冲突时以 created_at 最新的为准
```

### 每周汇总（daily → weekly）

用户说"汇总记忆"或每周五时：

1. 读取本周所有 daily 文件
2. 去重、合并同类项
3. 只保留有价值的记忆（去掉临时性的）
4. 写入 `D:\wwwroot\ai\ai_cache\memory\weekly\YYYY-Wxx.json`
5. 删除已汇总的 daily 文件

### 手动沉淀（weekly → archive）

用户说"沉淀记忆"时：

1. 读取所有 weekly 文件
2. 按类型分流：
   - 业务规则 → 写入 `D:\wwwroot\ai\ai_cache\memory\archive\YYYY-MM.json`（当月文件）
   - 踩坑记录 → 写入 `D:\wwwroot\ai\ai_cache\memory\archive\pitfalls.json`
3. 与已有 archive 去重（同 tags + 同 content 的不重复写入）
4. 冲突时以 created_at 最新的为准
5. 删除已沉淀的 weekly 文件

## 判断标准

### 该不该记录？问自己三个问题

1. **这是业务规则还是代码实现？** → 只记业务规则
2. **一个月后还有用吗？** → 只记有长期价值的
3. **这是最终结论还是中间过程？** → 只记最终结论

### 示例

**✅ 应该记录**：
- "异常报告单状态流转：待评审→评审中→已评审，只有创建人能提交申诉"
- "所有涉及金额的字段用 DECIMAL(12,2)，不能用 FLOAT"
- "导出 Excel 时必须用异步队列，不能同步导出超过 1000 条"

**❌ 不应该记录**：
- "修复了 reviewTimes 的计算错误"（纯代码 bug）
- "尝试用 Redis 缓存但效果不好"（中间讨论）
- "用户表有 50 个字段"（代码可查）
